# Pipeline Variant Search System - Production Guide

**Terminology (Industrial Standard):**
- **Pipeline Template** = Fixed stage architecture (Stages 0-11)
- **Pipeline Variant** = One configuration across Stages 2-4 (preprocessing + feature engineering)
- **Search Space** = Allowed options + constraints
- **Winning Variant (Locked)** = Config frozen for production retraining

---

## Overview

This system replaces ad-hoc "recipe" generation with a **production-grade configuration search** that:
✅ Enforces task-specific constraints (no SMOTE for regression, no target encoding for clustering)
✅ Assesses data leakage risk (HIGH for target encoding, MEDIUM for SMOTE outside CV)
✅ Supports progressive narrowing (cheap_eval → full_eval → HPO)
✅ Generates deterministic variant IDs (SHA1 hash for reproducibility)
✅ Exports locked manifests for production retraining


## Leakage Risk Assessment

### NONE (792 variants for classification)
- **Safe**: onehot/label encoding + no SMOTE + no model-based feature selection
- **Example**: `mean+onehot+standard+variance`

### LOW (432 variants)
- **Requires Attention**: RFE or Boruta feature selection (uses model internally)
- **Example**: `median+onehot+robust+rfe`
- **Mitigation**: Already cross-validated in implementation

### MEDIUM (4,896 variants)
- **Requires CV-Safe Implementation**: SMOTE/ADASYN/resampling
- **Example**: `knn+smote+onehot+standard+mutual_info`
- **Mitigation**: Must apply inside CV folds, NOT before split

### HIGH (6,120 variants)
- **Critical Leakage Risk**: Target encoding without CV
- **Example**: `mean+target+standard+none`
- **Mitigation**: Use sklearn TargetEncoder with CV, or exclude entirely

### Config-Level Recipe Selection

**Before (V3 original — legacy):**
```yaml
phases:
  phase_b_recipes:
    library: v1_generated
    tier: lightning_fast
    max_recipes: 2
```

**After (pipeline_builder.py auto-selects variants):**
```yaml
phases:
  phase_b_recipes:
    library: variant_search          # Use constraint-validated variants
    mode: progressive                # Options: progressive, grid_sample, random_sample
    max_variants: 20                 # Number of variants to test
    runtime_budget_sec: 120          # Optional: cheap_eval filter
    exclude_high_leakage: true       # Exclude target encoding without CV
    seed: 42                         # Reproducibility
```

> **Pipeline wiring**: `pipeline_builder.py` joins selected variant paths into a
> comma-separated string and passes it to the `variants_list` input of s06.

### Progressive Narrowing Workflow

**Phase B (Cheap Eval):**
```yaml
variant_search:
  mode: progressive
  max_variants: 50
  runtime_budget_sec: 180  # 3 minutes per variant
  cheap_eval:
    timeout: 120
    cv_folds: 3
    engines: [flaml]  # Fast engine only
```

**Phase B-2 (Full Eval on Top-K):**
```yaml
variant_search:
  mode: locked
  top_k_from_cheap_eval: 5
  full_eval:
    timeout: 600
    cv_folds: 5
    engines: [pycaret, flaml]
```

## Constraint Validation Rules

### Classification
- ✅ All dimensions available
- ✅ SMOTE/imbalance methods allowed
- ✅ Target encoding allowed (with HIGH leakage warning)
- ✅ chi2 feature selection allowed

### Regression
- ✅ Outlier handling instead of imbalance
- ❌ SMOTE/imbalance methods **BLOCKED**
- ❌ chi2 feature selection **BLOCKED**
- ✅ Target encoding allowed (with HIGH leakage warning)

### Clustering
- ✅ No target column, simplified dimensions
- ❌ Target/CatBoost encoding **BLOCKED**
- ❌ Imbalance methods **BLOCKED**
- ❌ chi2 feature selection **BLOCKED**

## Best Practices

### 1. Start with Cheap Eval (Progressive Mode)
```bash
# Generate 50 fast variants (< 2 min each)
python configs/generate_variant_library.py \
  --task_type classification \
  --mode progressive \
  --max_variants 50 \
  --runtime_budget_sec 120
```

### 2. Exclude High Leakage Unless CV-Safe
```bash
# Only use if target encoding implemented with CV
python configs/generate_variant_library.py \
  --task_type classification \
  --exclude_high_leakage  # RECOMMENDED
```

### 3. Lock Winning Variant for Production
```python
# After Phase B/C, export locked manifest
engine.export_locked_manifest(
    winning_variant=champion,
    performance_metrics=final_metrics,
    output_path="outputs/locked_variant_manifest.json"
)
```

### 4. Rescan on Drift Detection
```yaml
retraining_instructions:
  allow_drift_rescan_threshold: 0.05  # 5% metric drop
```

If production accuracy drops > 5%, trigger new variant search instead of blindly reusing locked config.

## FAQ

### Q: What's the difference between "recipe" and "variant"?
**A:** "Recipe" is informal. Use **Pipeline Variant** in docs/UI, keep "recipe" in code for backward compatibility.

### Q: How many variants should I test in Phase B?
**A:** 
- **Lightning fast**: 10-20 variants (< 2 min each) = 20-40 minutes total
- **Balanced**: 50 variants (< 3 min each) = 2.5 hours total
- **Exhaustive**: 100+ variants = 5+ hours

### Q: Should I exclude HIGH leakage variants?
**A:** **YES** unless you implement CV-safe target encoding with sklearn pipelines. Otherwise, variant scores will be inflated and not generalize.

### Q: Can I use Optuna/Bayesian search instead?
**A:** Partially implemented. Set `mode: bayesian` but requires objective function integration with Phase B training. Use progressive narrowing for now.
