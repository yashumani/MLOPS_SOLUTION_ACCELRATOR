## Relationships to draw

- Operator → React or Streamlit → FastAPI over HTTP(S). Frontend runtime configuration selects the API base URL (`react-ui/src/services/runtimeConfig.ts:14`); Streamlit sends API-key requests (`ui/api_client.py:14`). Entra login applies to the React multi-user deployment (`react-ui/src/services/entraSession.ts:16`).
- FastAPI → canonical submit CLI → Azure ML pipeline. The subprocess returns a structured submission result; API workers update durable request state (`api/services/pipeline_service.py:526`, `api/services/pipeline_service.py:591`).
- FastAPI → Azure ML SDK → jobs, experiment metadata, cancellation, artifacts and schedule inspection (`api/core/azure_ml.py:16`, `api/services/pipeline_service.py:736`, `api/services/auto_retrain_service.py:170`). The backend uses a managed-identity/CLI credential chain, separate from the browser's user token (`api/core/azure_ml.py:21`).
- Azure ML drift and S14 outputs → controller validation → decision ledger reservation → canonical submit CLI → candidate pipeline. Completed candidates remain pending manual promotion; uncertainties go to reconciliation (`src/orchestration/automated_retrain_controller.py:113`).
- Operator baseline approval → Azure job/artifact identity checks → approved comparison baseline in ledger → future controller plan (`api/services/auto_retrain_service.py:283`, `src/orchestration/auto_retrain_controller.py:125`).
- API and controller → local durable SQLite state; report service → report files and optional SMTP server. This is a single-host state architecture, not an external distributed queue/database (`src/orchestration/operational_state.py:1`, `api/services/pipeline_service.py:584`, `api/services/notification_service.py:449`).

## Required diagram caveats

1. Draw the controller, API, UI and Azure ML as implemented components, not as currently deployed healthy services. No live acceptance was performed for this evidence note.
2. Candidate retraining is distinct from model promotion or endpoint deployment. Auto-promotion is false by default (`src/orchestration/auto_retrain_policy.py:34`); successful daemon submission records `manual_pending` (`src/orchestration/automated_retrain_controller.py:160`). No API endpoint for deploying a model is defined in the inspected routers.
3. An approved drift baseline is not a promoted production model. Baseline capture only discovers a URI; approval performs the identity checks (`api/services/pipeline_service.py:1798`, `api/services/auto_retrain_service.py:412`).
4. Schedule rows do not prove an active schedule. Failed Azure listing becomes `unverified`; successful listing without a match becomes `missing` (`api/services/auto_retrain_service.py:186`). The compatibility schedule script performs no Azure mutation (`scripts/setup_drift_schedule.py:88`).
5. React Logs reconstructs job and step timeline events; it is not a streaming raw-log endpoint (`react-ui/src/pages/Logs.tsx:19`). Streamlit's log page falls back to status text and an Azure ML Studio link when the job response lacks log text (`ui/pages/7_Live_Logs.py:137`).
6. `/api/v1/health` sets `azure_ml_connected` after constructing/reusing the ML client, without issuing a workspace request (`api/routers/health.py:13`). That field is not proof of Azure API reachability. `/healthz` is only liveness (`api/main.py:228`).
7. Durable request records survive API restarts, but the worker queue itself is in-process. Stale pending requests search Azure for matching `submission_request_id` tags and otherwise require reconciliation; they are not automatically resubmitted (`api/services/pipeline_service.py:666`).
8. Historical child-step visibility may include stages explicitly inferred from named parent outputs, not direct child execution evidence (`api/services/pipeline_service.py:234`).
9. `private_single_operator` and `multi_user` startup checks require explicit HTTPS origins, durable paths, no reload and disabled checkout mutation; multi-user additionally requires Entra configuration and local-disk SQLite (`api/core/config.py:79`). These checks do not prove that a deployed instance is configured this way.
10. The launcher starts FastAPI on loopback port 8000 and Streamlit on loopback port 8501 by default (`scripts/run_app.sh:16`). React also defaults to port 8501 (`react-ui/package.json:7`), so draw the two frontends as alternatives unless separate deployment evidence establishes concurrent ports. The Streamlit endpoint YAML is commented reference material and explicitly warns that Online Endpoints are not the UI host (`ui/azureml-streamlit-deployment.yml:1`).
11. GitHub Actions defines backend contract tests, Python dependency audits, React type checks/tests/build and Playwright checks (`.github/workflows/release-candidate-ci.yml:21`, `.github/workflows/release-candidate-ci.yml:72`). This is a source-defined gate; its latest hosted status was not queried.
